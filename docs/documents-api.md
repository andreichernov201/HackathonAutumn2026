# Контракт документов

`DocumentProject` — единый серверный объект с постоянным `projectId`, `templateId`, технической `templateVersion` (SHA-256 исходника), `fields`, `status`, `version`, датами, `validation`, `preview` и `artifacts`. `generated` означает только наличие файла, не официальное утверждение.

`DocumentTemplate.sourceStatus`: `ready` означает, что структура синтетического исходника проходит проверку обработчика и форма доступна; это не официальный статус. `awaiting_schema` означает несовместимую или непроверенную структуру, `awaiting_review` — состояние после закрытой админ-загрузки. `registryStatus` пока `unverified`. Исходные файлы — синтетические материалы кейса, не реестр утверждённых модулей.

`POST /api/document-projects` принимает `{ "templateId": "working-group-order", "title": "..." }`. `PATCH` принимает `{ "expectedVersion": 1, "fields": { "purpose": "..." }, "title": "..." }`; `fields` — частичное обновление. `POST .../preview` принимает `{ "fields": {...} }` и возвращает `{ "preview": [...], "validation": {...} }` без записи. Проверка возвращает ошибки с кодами и привязкой к полям. Генерация блокируется при неполном наборе полей и смене версии источника.

`GET /api/document-tools` выдаёт разрешённые имена, REST маршруты, JSON Schema входа и выхода. `POST /api/document-tools/{name}/invoke` принимает `{ "arguments": {...} }` и использует тот же сервис и права. В реестре нет необратимых операций. Загрузка и подтверждение источника закрыты (`403`) в демо без авторизации.

Демо-сеанс: `GET /api/session` выдаёт `deviceId` и `csrfToken`, а сервер устанавливает подписанную HttpOnly cookie. Для `POST` и `PATCH` передавайте `X-CSRF-Token`. Скачивание требует cookie и проверки владельца проекта и артефакта. Проекты хранятся на сервере отдельно для каждого браузера; потеря cookie означает потерю доступа к прежним проектам. Это не авторизация для публичного сервиса: развёртывайте только локально или за доверенным контуром.

## Схемы семи модулей

Схемы возвращаются в `GET /api/document-templates/{id}` как список `fields` с `required`, `inputType` и `options`. Для комитета и аудита есть выбор единственного/множественного числа; для приказа о вводе ИС — выбор «разработанного/измененного»; для назначения ответственных строки списка имеют формат `подразделение | должность, инициалы и фамилия`. Даты и условные реквизиты отмены проверяются сервером. Все обработчики копируют исходный DOCX и отказывают при изменении ожидаемой структуры.

Для `local-act-order` поле `attachmentName` фиксирует название подготовленного приложения, но сервис не загружает и не прикрепляет приложение; его надо оформить отдельно до использования проекта. Метаданные проекта не являются карточкой ИИС ДО. Статус реестра всех модулей остаётся `unverified`; применение п. 1.3 Методических рекомендаций не заявляется.
