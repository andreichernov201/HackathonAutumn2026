# Контракт документов

`DocumentProject` — единый серверный объект с постоянным `projectId`, `templateId`, технической `templateVersion` (SHA-256 исходника), `fields`, `status`, `version`, датами, `validation`, `preview` и `artifacts`. `generated` означает только наличие файла, не официальное утверждение.

`DocumentTemplate.sourceStatus`: `ready` означает, что структура синтетического исходника проходит проверку обработчика и форма доступна; это не официальный статус. `awaiting_schema` означает несовместимую или непроверенную структуру, `awaiting_review` — состояние после закрытой админ-загрузки. `registryStatus` пока `unverified`. Исходные файлы — синтетические материалы кейса, не реестр утверждённых модулей.

`POST /api/document-projects` принимает `{ "templateId": "working-group-order", "title": "..." }`. `PATCH` принимает `{ "expectedVersion": 1, "fields": { "purpose": "..." }, "title": "..." }`; `fields` — частичное обновление. `POST .../preview` принимает `{ "fields": {...} }` и возвращает `{ "preview": [...], "validation": {...} }` без записи. Проверка возвращает ошибки с кодами и привязкой к полям. Генерация блокируется при неполном наборе полей и смене версии источника.

`GET /api/document-tools` выдаёт разрешённые имена, REST маршруты, JSON Schema входа и выхода. `POST /api/document-tools/{name}/invoke` принимает `{ "arguments": {...} }` и использует тот же сервис и права. В реестре нет необратимых операций. Загрузка и подтверждение источника закрыты (`403`) в демо без авторизации.

Демо-сеанс: `GET /api/session` выдаёт `deviceId` и `csrfToken`, а сервер устанавливает подписанную HttpOnly cookie. Для `POST` и `PATCH` передавайте `X-CSRF-Token`. Скачивание требует cookie и проверки владельца проекта и артефакта. Проекты хранятся на сервере отдельно для каждого браузера; потеря cookie означает потерю доступа к прежним проектам. Это не авторизация для публичного сервиса: развёртывайте только локально или за доверенным контуром.

## Схемы семи модулей

Схемы возвращаются в `GET /api/document-templates/{id}` как список `fields` с `required`, `inputType` и `options`. Для комитета и аудита есть выбор единственного/множественного числа; для приказа о вводе ИС — выбор «разработанного/измененного»; для назначения ответственных строки списка имеют формат `подразделение | должность, инициалы и фамилия`. Даты и условные реквизиты отмены проверяются сервером. Все обработчики копируют исходный DOCX и отказывают при изменении ожидаемой структуры.

Для `local-act-order` поле `attachmentName` фиксирует название подготовленного приложения, но сервис не загружает и не прикрепляет приложение; его надо оформить отдельно до использования проекта. Метаданные проекта не являются карточкой ИИС ДО. Статус реестра всех модулей остаётся `unverified`; применение п. 1.3 Методических рекомендаций не заявляется.

## Живой DOCX-предпросмотр и подсветка полей

`POST /api/document-projects/{projectId}/preview-file` принимает `{ "fields": {...} }` — полный снимок текущих значений формы, включая несохранённые. Пропущенные ключи считаются пустыми; сохранённые значения не подмешиваются. Требуются cookie владельца и `X-CSRF-Token`, как для остальных операций записи. Неверный ID и чужой проект возвращают одинаковый `404 project_not_found`.

Ответ — бинарный DOCX с MIME `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `Content-Disposition: inline; filename="preview.docx"`, `Cache-Control: private, no-store` и `X-Content-Type-Options: nosniff`. Старый JSON-маршрут `/preview` продолжает работать.

Все семь шаблонов используют существующие рендереры: для рабочей группы добавлен `draft=True`, остальные используют прежний режим черновика. Пустые поля допустимы. Неизвестные ключи, значения другого типа, недопустимые даты и варианты выбора, ошибки формата таблицы, управляющие символы XML и значения длиннее 4000 символов отвергаются. Общая длина значений ограничена 128 000 символами; действует также общий лимит HTTP-запроса. Отсутствие обязательных и зависимых полей не блокирует предпросмотр. Необязательный блок отмены скрывается, пока не введён хотя бы один его реквизит.

Временные подстановки получают заливку текста Word (`w:shd`): пустые — `FEF3C7` и подсказку «Укажите: …», заполненные — `DBEAFE`. Отмечаются только вставленные значения, включая даты, повторные вхождения, многострочный текст и ячейки таблиц. Совпадающие слова в постоянном тексте не подсвечиваются. Названия подсказок берутся из схемы полей. Служебные зоны регистрации и подписи остаются исходными. Служебные маркеры существуют только внутри одного вызова и удаляются перед возвратом DOCX; шрифты и остальные свойства исходных фрагментов сохраняются.

Сервис читает проект, схему и исходник, создаёт новую копию DOCX в памяти и возвращает байты. Он не вызывает сохранение или финальную генерацию, не создаёт артефактов и не меняет поля, версию, статус или дату изменения. Финальный маршрут по-прежнему проходит полную валидацию и вызывает рендереры без режима черновика и подсветки.

`documentsApi.previewFile(projectId, fields, signal?)` возвращает `Promise<Blob>` через общий клиент с CSRF. Компонент `DocumentLivePreview` передаёт Blob в общий `DocumentViewer`, обновляет его через 450 мс после ввода, отменяет предыдущий запрос и игнорирует устаревшие ответы. При ошибке показывает сообщение; прежний документ явно помечается как предыдущая версия. Скачивание временного файла в панели отключено. Сохранённые версии скачиваются обычным способом без подсветки. JSON-предпросмотр доступен под «Текст документа».

Ограничения: разбиение DOCX в браузере может отличаться от Word; поля, являющиеся только метаданными проекта, не добавляются в тело документа. Фокус поля формы и переход к соответствующему месту в документе можно добавить на следующем этапе.

Проверки: `python -m pytest api/tests/test_preview_file.py api/tests/test_documents.py api/tests/test_modules.py` проверяет реальные семь шаблонов, пустые/частичные/полные значения, структуру и оформление, отсутствие записей, права и CSRF, параллельную изоляцию и чистоту финальных DOCX. `playwright test tests/e2e/preview-fields.spec.ts` проверяет реальные цвета в браузере для рабочей группы и приказа о назначении ответственных, таблицы, обновление после очистки поля, сохранность подсветки после поиска и защиту от устаревших ответов.
