## Исправления

- Убрано локальное ограничение Nginx 10 MiB в `/api/`. Frontend и KnowledgeService принимают файл до 20 MiB; Nginx/FastAPI — запрос до 22 MiB с multipart overhead. FastAPI ограничивает фактически прочитанный поток и запрос без Content-Length.
- Убран публично известный стандартный ключ сессии. В локальной разработке без настроенного ключа создаётся временный случайный ключ; заданные ключи проверяются. Production требует приватный ключ минимум 32 символа и Secure cookie. Образ API по умолчанию использует production; Compose явно задаёт локальную разработку и публикует только Nginx на localhost.
- Вход/выход администратора базы знаний сохраняют срок общей cookie устройства. Отдельный восьмичасовой grant ограничивает административные права, не сокращая срок доступа к собственным проектам.
- Документы, загрузки, скачивание и будущий chat API используют общий HTTP-клиент, cookies, bootstrap сессии, CSRF и обработку ошибок. При отсутствующем `/api/chat` API-адаптер сообщает о неподключённой Qwen.
- Из demoGateway удалён второй корпус захардкоженных нормативных выдержек. Недоступная проверка файлов сообщает, что файл не прочитан. Обычные текстовые вопросы используют оригиналы KnowledgeService.
- Общий реестр `/api/tools` объединяет 16 существующих инструментов с уникальными именами и строгими схемами. Диспетчер вызывает исходные сервисы, сохраняя владельца проекта, ACL базы и CSRF. Прежние маршруты совместимы.
- Ответы проверки/генерации не затирают последующие правки полей и заголовка. Редактор сохраняет несохранённые данные при переходах между разделами.
- Серверный предпросмотр показывает таблицу с одним назначенным сотрудником, как и DOCX.
- Добавлены healthcheck API, ожидание готовности в Compose, backend-интеграции, браузерные регрессии и полный контейнерный smoke в CI.

## Проверки

Локально выполнены `npm ci`, `npm run build`, `python -m pytest -q api/tests`: 23 backend-теста, включая пять новых интеграций. В Chrome с изолированной базой прошли четыре браузерных сценария, включая задержанные ответы проверки/генерации и реальное скачивание DOCX. Исходные DOCX и нормативные оригиналы проверяются по неизменным байтам/SHA-256. Проверяются все семь модулей, п. 2.1 рекомендаций, строка 6 матрицы, ACL, переиндексация и сохранение ссылок.

Docker на локальном компьютере отсутствует. Поэтому workflow CI выполняет `docker compose config --quiet`, `docker compose up --build --wait`, браузерные проверки через Nginx и `scripts/compose-smoke.py`. Smoke проверяет три оригинала, 16 инструментов, полный цикл семи DOCX, общую сессию и загрузку 20 MiB с multipart, а также 413 выше 22 MiB. Статус конкретного запуска доступен в GitHub Actions; интеграционный PR объединяется только после успешных проверок.

## Рабочие компоненты и границы

Работают единый FastAPI/SQLite, DocumentsService, KnowledgeService, семь DOCX-модулей, серверные проекты/версии/предпросмотр/скачивание, FTS5, оригиналы, цитаты, ссылки на пункты, общий реестр инструментов, сессия и CSRF. Интерфейс чата выполняет реальный нормативный поиск; история хранится в localStorage. Оба сервиса используют `REGULA_DATA_DIR/documents.sqlite3`; дубликатов маршрутов нет. Главная страница и стили сохранены.

Qwen, генеративные ответы, embeddings, OCR, автоматическая проверка загруженных пользовательских файлов, построение подтверждённого маршрута визирования, корпоративный SSO и фактические действия в ИИС ДО не реализованы. Предпросмотр — серверное представление содержания, не изображение страниц DOCX. Три импортированных оригинала являются синтетическими материалами кейса с неподтверждёнными редакциями, не действующими нормативными актами Банка России.

Архитектурная основа для подключения Qwen готова: единые инструменты, данные, сессия и HTTP-контракт. Следующие приоритеты: серверный оркестратор с проверкой цитат и сохранением контекста; правила применимости редакций/п. 1.3/маршрута главы 10; полноценная проверка пользовательского документа; корпоративные права/HTTPS/аудит; интеграция с ИИС ДО и подтверждение реквизитов исходников.
