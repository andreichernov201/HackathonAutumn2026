# Как устроен проект

Сейчас это один фронтенд. Мы не связываем его напрямую с RAG, Qwen или генератором DOCX: сначала нужен сервер, который примет запрос, решит, какой инструмент вызвать, и вернёт результат.

## Где что лежит

- `src/App.tsx` собирает экран и держит текущий диалог. Здесь почти нет разметки.
- `src/components/` содержит части интерфейса: меню, стартовый экран, диалог, поле ввода и пустые разделы.
- `src/features/assistant/` содержит сценарии, типы запросов, временный адаптер ассистента и локальную историю.
- `src/app/navigation.ts` описывает разделы меню. Общие мелкие функции лежат в `src/shared/`.

Так можно добавлять отдельные функции без большого общего файла. Например, проверка документов может получить свою папку `src/features/check/`, а база знаний — `src/features/knowledge/`.

## Когда появится сервер

Замените временную реализацию в `gateway.ts` на вызов своего API. В `ChatRequest` уже передаются текст, сценарий и выбранный файл. Сейчас адаптер возвращает `not-configured`, поэтому интерфейс показывает честное сообщение об отсутствии ответа. При настоящем ответе он умеет показать сообщение ассистента.

Локальная история находится в `sessionStore.ts`. Для аккаунтов и работы с разных устройств её нужно заменить серверным хранением. Текущий `localStorage` подходит только для прототипа.

Правую панель стоит показывать, когда сервер действительно вернул источники, маршрут визирования или другой результат для неё. В пустом чате панель не нужна.

Docker-образ содержит только статический фронтенд. API, база данных, индекс поиска и очередь задач должны жить отдельно. Адреса и настройки для них добавим вместе с реальной интеграцией, чтобы сейчас не оставлять неработающие переменные.
