# Как устроен проект

Сейчас это фронтенд с ограниченным демо адаптером. Он не обращается к RAG, модели или генератору DOCX. Для реального процесса нужен сервер, который проверяет полномочия, ищет положения в версионированном корпусе и возвращает структурированный ответ.

## Где что лежит

- `src/App.tsx` собирает экран и держит текущий диалог. Здесь почти нет разметки.
- `src/components/` содержит части интерфейса: меню, стартовый экран, диалог, поле ввода и пустые разделы.
- `src/features/assistant/` содержит типизированный контракт, демо адаптер, переключаемый API адаптер и локальную историю.
- `src/app/navigation.ts` описывает разделы меню. Общие мелкие функции лежат в `src/shared/`.

Так можно добавлять отдельные функции без большого общего файла. Например, проверка документов может получить свою папку `src/features/check/`, а база знаний — `src/features/knowledge/`.

## Когда появится сервер

При `VITE_CHAT_BACKEND=api` фронтенд отправляет `ChatRequest` на относительный `POST /api/chat`: ID диалога, сообщение, историю и контекст проекта/панели. Ответ `ChatResult` содержит блоки `citation`, `task_progress`, `clarification`, `document_card`, `validation_result`, ссылки на источники и обновлённый проект. FastAPI должен проверять права доступа к диалогу, валидировать схему, ограничивать размер истории, хранить версии документа и журнал действий. Доступ к Ollama и индексу допускается только из внутренней сети сервера.

Демо адаптер выдаёт ответы лишь по трём положениям, переданным в условиях кейса: п. 2.1 и п. 1.3 Методических рекомендаций и строка 6 раздела «Внутренние документы» матрицы. Ссылки ведут к конкретным выдержкам в панели; URL оригиналов не выдуманы. Неизвестный вопрос получает отказ. Строка матрицы сообщает участников, а последовательность визирования требует главы 10 Инструкции. Демо не утверждает, что согласование состоялось.

Локальная история находится в `sessionStore.ts`. Для аккаунтов и работы с разных устройств её нужно заменить серверным хранением. Текущий `localStorage` подходит только для прототипа.

Правая панель скрыта в новом чате. Она открывается с результатом, её можно свернуть и открыть снова. Демо проект хранится в том же объекте сессии, который передаётся в запрос и редактируется полями.

Docker-образ содержит только статический фронтенд. API, база данных, индекс поиска и очередь задач должны жить отдельно.

## Приоритет до защиты

1. Загрузить подлинники Инструкции, матрицы и рекомендаций с версиями, правами доступа и устойчивыми адресами пунктов; проверить точность демонстрационных выдержек.
2. Реализовать FastAPI `/api/chat` с поиском, обязательными цитатами, уточняющими вопросами и отказом без источника. Добавить аутентификацию, изоляцию сессий, аудит и защиту от подсказок в документах.
3. Подключить утверждённые модульные DOCX шаблоны, заполнять их сервером, вести версии и проверять исключения п. 1.3.
4. Извлечь правила главы 10 Инструкции и реализовать проверяемый порядок визирования отдельно от состава подразделений в матрице. Интеграцию с 1С и фактические статусы согласования показывать только после подтверждённого обмена.
