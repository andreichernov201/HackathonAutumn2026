# Архитектура Regula AI

React/TypeScript/Vite frontend обращается к единому FastAPI `api.main:app` через same-origin `/api`. Nginx и Vite проксируют запросы. `DocumentsService` и `KnowledgeService` используют одну SQLite `REGULA_DATA_DIR/documents.sqlite3`, одну подписанную HttpOnly-сессию и CSRF-защиту. SQLite, исходные файлы и артефакты находятся в одном локальном каталоге/volume. Внешние AI API не обязательны.

## Модули

- `src/App.tsx` — разделы, история чата, связь серверного проекта и выбранного источника с чатом.
- `src/features/documents/`, `DocumentsPage` — существующий редактор, каталог семи модулей, версии DOCX.
- `api/service.py`, `api/models.py`, `api/working_group.py` — существующий сервер документов. Его таблицы/API не заменены.
- `src/features/knowledge/` — каталог, API-клиент, загрузка, просмотрщик с деревом, оригиналом и сведениями об источнике.
- `api/knowledge/` — Pydantic-модели, разбор PDF/DOCX/TXT, прикладной сервис, HTTP-router, типизированные AI-инструменты, миграции и три пользовательских учебных оригинала.
- `src/shared/http.ts` — общий bootstrap сессии и CSRF для документов и базы знаний. Один запрос сессии предшествует параллельным чтениям, чтобы cookie и CSRF не разошлись при первом посещении.
- `src/features/assistant/` — существующий контракт `ChatResult`, API-адаптер, локальная история. Нормативные текстовые запросы без Qwen возвращают реальные поисковые выдержки, а не зашитый демо-корпус.
- `WorkspacePanel`, `ChatBlocks` — прежние citation-блоки совместимы; реальные ссылки содержат `sectionId/versionId`, открывают исходный пункт и соответствующий оригинал.

## Нормативный путь

Оригинал → проверка размера/формата → локальное извлечение → неизменная редакция и пункты → FTS5/русский стемминг → проверяемая цитата → каталог/панель чата. Чанки для будущего RAG хранятся отдельно от структуры пунктов. Переиндексация не меняет текст и адреса источников.

Классификация `synthetic` сохраняется в БД, цитатах и интерфейсе. Импортированные материалы не объявлены действующими; последний upload не становится применимой редакцией автоматически. Шаблоны остаются в существующем реестре документов и исключены из нормативного поиска по умолчанию.

## AI и границы доверия

`GET /api/knowledge/tools` публикует шесть allowlisted инструментов с JSON Schema. Их HTTP-вызовы и интерфейс используют одну бизнес-логику, проверяющую роль. Оркестратор передаёт извлечённый текст как недоверенные tool-данные, выбирает подходящую редакцию и обязан проверить каждую цитату через `verify_citation`. Произвольные SQL, файловые пути, команды и роли от модели не принимаются.

Qwen, embeddings и серверный `/api/chat` пока не реализованы. Контракт и `VITE_CHAT_BACKEND=api` сохранены для разработчика оркестратора. Базовые каталог/поиск/просмотр работают автономно. Демо-вход по серверному ключу обслуживает базу знаний, но не заменяет корпоративный SSO; для production нужен проверенный principal из корпоративной авторизации.
