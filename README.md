# Regula AI

Regula AI: единый frontend React и backend FastAPI для документов и базы знаний. Главный экран, чат и сервис генерации DOCX сохранены. Проекты хранятся на сервере. Есть каталог семи модулей из синтетического кейса, поиск, создание и дублирование проектов, форма, серверный предпросмотр, проверка, версии и скачивание DOCX. Чат и редактор открывают один `projectId`.

Для всех семи предоставленных синтетических модулей действует путь: выбор модуля → заполнение его схемы → серверная проверка и предпросмотр → генерация из **копии соответствующего исходного DOCX** → скачивание → правка и новая версия. Схемы учитывают предусмотренные исходниками варианты: составы, даты, число проектов/процессов и необязательную отмену прежнего акта. Генератор удаляет гриф утверждения, подсказки, номера примечаний и пометку «МОДУЛЬНЫЙ ДОКУМЕНТ», сохраняет области даты, номера и ЭП. Техническая версия файла определяется SHA-256; официальный статус и редакция в реестре не подтверждены. Номер, подпись, виза и карточка ИИС ДО не создаются. Для приказа об утверждении локального акта приложение необходимо подготовить и приложить отдельно: сервис формирует только текст приказа и не проверяет фактическое наличие приложения.

## Запуск

```sh
cp .env.example .env
# Укажите длинный случайный REGULA_SESSION_SECRET в .env.
docker compose up --build
```

Откройте [Regula AI](http://127.0.0.1:8080), раздел «Документы» или [«База знаний»](http://127.0.0.1:8080/#knowledge). Вход не требуется: каждому браузеру выдаётся отдельное демо-пространство через подписанную HttpOnly cookie. Проекты хранятся на сервере в Docker volume `regula_data`; удаление cookie или очистка данных сайта делает прежние проекты недоступными с этого браузера. OpenAPI: http://127.0.0.1:8080/api/docs и `/api/openapi.json`.

Локальная разработка:

```sh
python3 -m venv .venv
.venv/bin/pip install -r api/requirements.txt
.venv/bin/uvicorn api.main:app --reload --port 8000
npm ci
npm run dev
```

Без заданного секрета локальный запуск использует случайный временный ключ; для сохранения сессий после перезапуска задайте приватный `REGULA_SESSION_SECRET` длиной от 32 символов. Известные стандартные значения и короткие ключи отклоняются.

Vite перенаправляет `/api` на FastAPI. Тесты: `.venv/bin/python -m pytest -q api/tests`; сборка: `npm run build`.

## API

| Действие | Маршрут |
| --- | --- |
| Каталог и модуль | `GET /api/document-templates`, `GET /api/document-templates/{id}` |
| Создать и перечислить проекты | `POST /api/document-projects`, `GET /api/document-projects` |
| Открыть, изменить, предпросмотреть | `GET /api/document-projects/{id}`, `PATCH /api/document-projects/{id}`, `POST /api/document-projects/{id}/preview` |
| Проверить и сформировать | `POST /api/document-projects/{id}/validate`, `POST /api/document-projects/{id}/generate` |
| Версии и файл | `GET /api/document-projects/{id}/versions`, `GET /api/document-projects/{id}/artifacts/{artifactId}/download` |
| Реестр инструментов для AI | `GET /api/document-tools`, `POST /api/document-tools/{name}/invoke` |
| Загрузка исходников | Отключена в открытом демо (`403`); включать только после добавления корпоративной авторизации |

`PATCH` требует `expectedVersion` и возвращает `409 version_conflict` при конкурентной правке. Все действия проходят через `DocumentsService`, в том числе вызовы через реестр инструментов. Запросы и скачивание проверяют владельца. Реестр выдаёт разрешённые имена и JSON Schema аргументов; произвольный код от LLM не исполняется. Демо-сеанс выдаёт подписанную HttpOnly cookie, изменения требуют CSRF-токен. Это разделение браузеров, а не проверка личности: запуск ограничен `127.0.0.1`; перед общедоступным развёртыванием нужны корпоративная авторизация, HTTPS и аудит.

Типы и клиент для фронтенда: `src/features/documents/types.ts`, `src/features/documents/api.ts`. Подробности: `docs/documents-api.md`. Qwen и RAG ещё не подключены. Исключение п. 1.3 Методических рекомендаций автоматически не применяется: актуальность утверждённого модуля в реестре не проверена.

## База знаний

Реализованы загрузка PDF/DOCX/TXT, сохранение оригиналов и редакций, дерево пунктов, просмотр текста и таблиц, полнотекстовый поиск с русскими формами слов, постоянные ссылки, проверка цитат и контроль доступа. Используются тот же FastAPI, SQLite и сессии, что и для документов. Поиск работает без Qwen.

При первом запуске автоматически импортируются **три оригинала, предоставленные пользователем**: Инструкция по ДОУ (PDF, 51 страница), матрица визирования (DOCX), методические рекомендации (DOCX). Файлы и checksum находятся в `api/knowledge/sources/`. Все они синтетические учебные материалы, не нормативные акты Банка России. Статус редакций не подтверждён, даты действия и официальные редакции не придуманы. Семь DOCX-модулей уже присутствуют в сервисе документов и побайтово совпадают с присланными файлами.

Для загрузки/новых редакций задайте в `.env` `REGULA_KNOWLEDGE_ADMIN_TOKEN` (случайный ключ минимум 32 символа), затем откройте «Управление базой». Пустой ключ отключает обслуживание. Это локальный demo-режим, не корпоративная авторизация. Для пустой установки используйте `REGULA_IMPORT_CASE_CORPUS=0`. Уже импортированные данные эта настройка не удаляет.

Каталог: `GET /api/knowledge/documents`; поиск: `GET /api/knowledge/search?q=...`; пункт: `GET /api/knowledge/sections/{id}`. Реестр AI-инструментов: `GET /api/knowledge/tools`. Права проверяются и через HTTP, и при вызове инструмента. Обычные текстовые вопросы чата ищут в той же базе; результаты помечены как исходные выдержки, без имитации AI-анализа.

Примеры проверки: «Когда присваивается регистрационный номер проекту распоряжения?» находит п. 2.1 рекомендаций; вопрос о визировании рабочей группы для ИТ-проекта — строку 6 внутренних документов матрицы. Условия визирования не выдаются за выполненное согласование.

Не реализованы OCR, векторный поиск/embeddings, Qwen-оркестратор, сравнение редакций и корпоративный SSO. Работа каталога, поиска, оригиналов и цитат от них не зависит. Подробные API, схема, ограничения и подключение Qwen: [docs/knowledge-api.md](docs/knowledge-api.md).


## Интеграционный контракт

`GET /api/tools` и `POST /api/tools/{name}/invoke` объединяют 10 инструментов документов и 6 инструментов базы знаний. Имена уникальны, аргументы проверяются, неизвестные поля и инструменты отклоняются. Вызовы используют общие cookie/CSRF и вычисляют права на сервере; прежние API остаются совместимыми. Qwen/эмбеддинги не запущены; `VITE_CHAT_BACKEND=api` резервирует будущий `/api/chat` и использует тот же HTTP-клиент.

Лимит файла базы знаний — **20 MiB**, всего HTTP-запроса — **22 MiB** в FastAPI и Nginx (с учётом multipart). FastAPI ограничивает также поток без Content-Length. Недоступная проверка файлов не возвращает демо-ответы или захардкоженные нормативные выдержки.

Compose публикует только Nginx на `127.0.0.1:8080`. FastAPI и SQLite остаются внутри сети/volume, Ollama/Qwen отсутствуют. Для внешнего размещения требуется HTTPS-прокси и корпоративная авторизация: `REGULA_ENV=production`, приватный ключ от 32 символов, `REGULA_SECURE_COOKIE=1`. В production приложение отказывается стартовать с небезопасными настройками. Docker-образ API по умолчанию использует production; Compose явно задаёт локальный режим разработки.

В CI проверяется полный запуск: `docker compose config`, `docker compose up --build --wait` и HTTP smoke-тест через Nginx, включая допустимую загрузку 20 MiB. Скрипт `scripts/compose-smoke.py` требует отдельный тестовый volume и ключ администратора; не запускайте его на рабочих данных.

Браузерные регрессии: `npm run test:e2e` при запущенных frontend/API. По умолчанию используется `http://127.0.0.1:5173`; `REGULA_TEST_URL` меняет адрес, `REGULA_CHROME_PATH` позволяет использовать установленный Chrome вместо Chromium Playwright. Для отдельных тестовых данных запустите API с `REGULA_DATA_DIR` во временном каталоге и свободным портом; `REGULA_API_TARGET` задаёт Vite адрес этого API. Тесты проверяют реальные источники/серверный DOCX, переходы между разделами, историю и сохранность правок при задержанных ответах проверки/генерации.
